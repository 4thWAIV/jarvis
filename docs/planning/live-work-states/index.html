Working must mean real activity

A progress report could keep a Work item glowing as Working for ten minutes after an agent stopped. This change closes that false signal.

What changes now

PreviouslyWith this fix
Agent reports WorkingActivity unconfirmed
Verifying report animates as WorkingVerifying, without a working animation
Old saved Working labelNormalized on every read, including older server responses

Reports remain in history. A report can describe progress; it cannot prove current token generation. Unconfirmed does not mean definitely idle.

Still required: positive live tracking

No current source proves token generation for an exact Work assignment. This fix deliberately cannot display Working. The Work item must stay open for instrumentation.

  1. Bind a trusted provider stream to Work item, piece, execution, assignment epoch and turn.
  2. Accept sequenced generation evidence only for that active assignment. Reject replay, old epochs and unrelated shared-session activity.
  3. Clear evidence on tool waits, pause, completion, disconnect and restart. Expire fresh evidence using a monotonic clock.
  4. Expose the precise evidence age and provider limitation. Delayed telemetry cannot prove instantaneous token spend.

Owned brain streams expose TextDelta events but lack Work binding. External CLI transcripts expose turn starts, endings and delayed updates; these include tool waits and must remain unconfirmed until reliable instrumentation exists.

Validation and review

Store and API regressions cover repeated reports, historical Working values, restart, shared-session unrelated activity, tool events, list/detail/brain output and preserved intent. Browser checks cover no false working animation, including dependencies and older responses.

This is an isolated branch for review, not a deployment. The immediate false-state prevention is ready for review after checks; live token instrumentation remains outstanding.
