Two user settings; defaults assessed separately

Both behaviors are user-selectable requirements. Implement and test both choices for each setting. Assess initial defaults separately; choosing a default must not remove the other option or overwrite a saved preference.

Setting in Voice settingsUser choicesRequired behavior
When I stop the microphoneKeep captured words or Discard unfinished input.Both choices immediately stop new capture. Keep processes only audio captured before the stop and preserves the resulting words under the normal turn/submission rules. Discard invalidates unfinished input, pending commits and late recognition results. Keeping words is distinct from introducing a new automatic-send action.
When I switch away from JARVISContinue listening or Stop listening.Continue preserves an already explicitly enabled listening session. Stop releases capture and applies the user's keep/discard preference to unfinished input. Switching back does not silently restart listening. This setting cannot enable a microphone that is muted or off.

Persistence: save both preferences per user in the existing local settings/database system, restore them before input starts, and expose their current values in Voice settings. Do not use one user's preference as a global team choice. Preference changes apply to subsequent stop/visibility transitions; changing a setting must not itself submit, discard or start capture.

Validation: test all four combinations, reload persistence, account separation, tab ownership, late recognition and disconnected recovery. UI and brain-callable settings operations must share validation and return the same saved values. Provide English and Spanish labels and explanations.

Defaults: compare candidate defaults during local validation. For missing, unreadable or invalid settings, remain disarmed until the effective preferences are established; never infer permission to listen from storage failure.

Mute proposal: suspend PCM delivery to every consumer, stop automatic turn commitment and retain recognized text as an unsent draft. A device already open may remain open, visibly labelled. Unmute is explicit and begins a new capture epoch; it does not silently submit the old draft. This separate Mute behavior remains a proposal for review.

Incoming audio: quiet, owned and accurately reported

  1. Implement quiet reload first. Change mic.ts initialization, jarvis.ts startup and voiceInput.ts acquisition/retry gates. Read the persisted quiet preference before calling getUserMedia. Existing browser permission, unrelated clicks and AudioContext unlock do not authorize listening.
  2. Make actual readiness visible. Show Off, Muted, Starting, Listening, Busy or Unavailable from device and recognizer facts. Do not show Listening merely because a request to start was made. Expose control state to keyboard and assistive-technology users.
  3. Give one client ownership of listening. Coordinate tabs with the backend capture owner; reject silent takeover. Human activation selects the owner. Ownership expiry or owner loss releases permission and returns quietly. Other tabs stay disarmed. A quiet command revokes the applicable owner and propagates to sibling tabs; a new tab does not acquire the mic while waiting for a busy recognizer.
  4. Enforce quiet across every PCM consumer. Move gating ahead of frame-listener dispatch. Package listeners and future audio subscribers must obey the same authorization. A meter can use local device data only under the documented muted-device policy; that data must not escape to recognition or recording consumers.
  5. Implement both keep/discard behaviors behind the user setting. Snapshot the last allowed audio sequence at the click. Release capture immediately. Finish mode drains only that bounded prefix under a finishing epoch, waits for recognition coverage, then hands the preserved words to the normal turn/submission rules without introducing a new automatic-send action. Discard revokes both active and closing epochs, pending timers and late finals. A timeout leaves an explicit recoverable draft/error, never an incomplete automatic submission.
  6. Apply the saved background-listening setting and reconnect rules. Visibility never arms capture. Retries must recheck the same authorization epoch. Disconnect stops accepting input under the old epoch and saves recognized text only as an unsent draft; replace the current automatic buffered submission on voice-socket teardown.

Incoming audio: let the person finish

  1. Replace the unguarded hold callback. Refactor server.py:_Utterance so each timer carries the turn identity, activity revision and expected deadline. Recheck them immediately before committing. Cancelling a timer handle alone is not sufficient once its task has started.
  2. Keep the user’s turn during a pause. New accepted interim/final activity invalidates the pending commit and extends the same gathered turn. An unfinished interim must block commitment of older finalized words. Explicit typed Send remains intentional completion; reconcile or preserve any pending voice draft instead of merging it silently.
  3. Connect recognition progress to the originating capture. Compare capture and processed sequence watermarks, with bounded lag and a deadline. Do not infer readiness from global diagnostics or require a continuously recording queue to be permanently empty. A stall surfaces Retry/Finish/draft recovery rather than sending an old fragment.
  4. Use one patience setting across input and output. Remove scheduler clamps that let speech start sooner than the user-turn hold. Trial a four-second recognized-activity hold only after the race and backlog protection work. This is a local tuning candidate, not a claim of four seconds of acoustic silence or an approved optimal default.
  5. Recheck before audio begins. If the person resumes while the brain or synthesizer is working, revoke stale playback permission. Preserve their continuation. An action already executed cannot be undone by stopping audio; never replay or cancel unrelated tools implicitly.
Acceptance checkpoint

Deterministic-clock tests cover continuation just before/at/after the deadline, lag without changed interims, delayed finals, speech during synthesis, typed Send amid voice input and reconnect. The old timer cannot submit an extra or partial request.

Outgoing audio: readable replies and precise interruption

  1. Keep Matt’s readable timeline. Reuse independent full-text streaming and reply-specific Skip to end. Finish the partial-error status: send distinct successful, failed and cancelled outcomes so unfinished text does not appear complete when a provider fails.
  2. Keep three actions distinct. Skip the rest targets one reading; Stop speaking immediately silences audio; Cancel request targets a generation/job under that job’s own cancellation rules. None implies that an executed action has been reversed. Add callable equivalents and clear English/Spanish wording.
  3. Extend reading identity where required. Use the same targeted skip contract for direct replies, digests and requested readbacks. Discard matching queued/late audio without affecting the next reply. For approval readback, a skip leaves approval pending and never satisfies its completion gate. Preserve the normal visual review path.
  4. Correct playback outcomes. Replace the current failed-decode-as-played behavior with distinct queued, started, played, failed, skipped and interrupted results. Keep transport advancement separate from actual playback and from human read/acknowledgment. Persist only the presentation facts needed for recovery.
  5. Make spoken delivery shorter. Keep full detail on screen; ask the brain for concise direct speech or bounded background summaries through the existing narration policy. Preserve exact requested quotations and approval payloads. Use phrase/sentence boundaries for natural pauses without adding a second browser timing loop or slowing every word.
  6. Protect against echo without hiding the user. Exercise existing browser echo cancellation and playback-aware matching with overlapping human speech on normal speakers. Test short stop/no/wait, repeated phrases, low volume and both output providers if selected. Fix reproduced echo failures before enabling new sounds; microphone muting during all readback is not a substitute for hearing the person.
Acceptance checkpoint

Skip silences only its target and keeps text/work. Late audio never revives skipped speech. Decode failures are not recorded as played. A skipped approval cannot approve or send. Physical speaker tests demonstrate that the selected output path can hear interruptions without treating JARVIS’s own voice as new requests.

Outgoing audio: fewer announcements, no scripted fallback chatter

  1. Store attention before announcing. Add attention references and presentation outcomes to existing SQLite storage, linked to original message/run/task IDs and revisions. Preserve source history. Deduplicate evolving events for one item instead of speaking each lifecycle change.
  2. Route every routine producer through one policy. Cover agent/team arrivals, needs boards, delivery receipts, run completions/stalls/failures, reconnect greetings and package endings. Keep status changes visible; severity alone must not bypass the user’s conversation or quiet setting.
  3. Remove automatic scripted sentences. Replace conversational hard-coded greetings, filler, acknowledgments and fault paragraphs with structured facts and visual diagnostics. Keep localized UI text and logs. Exact user-requested readback remains supported. Add a static call-site check and runtime sink tests so a helper cannot quietly reintroduce direct speech.
  4. Offer one bounded brain-written summary. Feed a read-only digest operation the current eligible facts, with external text wrapped as untrusted content. Give it no action tools. It may return a short summary or silence. If either configured brain provider is unavailable, retain visual items; do not substitute canned speech.
  5. Gate the summary with the same conversation controller. Block during pending input, recognition backlog, thinking, playback or approval. Recheck record revisions and activity immediately before playback. For a local trial, use the earlier proposal’s 60-second event age, 120-second digest cooldown and ten seconds after a settled exchange; all gates must pass. These are tuning candidates, not promises about human presence.
  6. Provide a quiet return experience now. Explicit Quiet/Away and unknown availability suppress routine speech. Use trusted current-session interaction as evidence of recent engagement, never socket connectivity alone. On return, show a grouped pending count and Review updates; do not play a backlog. Reuse existing arrival leases to avoid duplicate announcements across nodes.
  7. Keep existing transmission approvals intact. A summary, cue or incoming event cannot accept, send, execute or alter approval state. Keep urgent status visible. Any future exception that may interrupt must have an explicit policy, not an event payload declaring itself urgent.
