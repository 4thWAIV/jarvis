What is missing today

RightPanel and CentreArea each hold selected tabs in local React state. CentreArea reacts separately to openWorkflow, openThread, openDiagnostics, openSubsystem, openNetwork, openQueue and showFolders. Nested filters, selected files and subtabs introduce more local navigation state.

transferEndpoints.ts resolves agent and queue targets through DOM queries. Its fallback to a tab is useful for a transmission notification but cannot stand in for circling an exact hidden object. rayGeometry.ts routes specifically from the orb through the right-hand transmission lane. That route is not a general-purpose path to every screen location.

tool_show_on_screen in jarvis/server.py publishes structured display content to voice pages. It does not navigate, discover target geometry or wait for a browser’s acknowledgement. New UI control needs an explicit request/result protocol rather than returning “shown” immediately after enqueueing a broadcast.

One registry, two responsibilities

Navigation commands

What can be opened, selected, expanded, filtered, scrolled or closed. Each command defines arguments, availability, effects and one handler.

Visual targets

What can be indicated. Each target has an identity, parent, label, presentation location, visibility and geometry adapter.

Shared execution

Buttons, keyboard controls and brain requests invoke the same registered handler. No second implementation for the brain.

Keep these as separate concepts in one feature registration. A metric can be highlighted without being actionable. A command can reveal an unmounted object before it has screen bounds. A delete control can be indicated without allowing the navigation system to execute it.

Represent panel selection separately from keyboard focus. Selecting a central tab makes its content visible. Keyboard focus only moves to a registered focusable target when requested; do not steal a text cursor just to circle a number. The current left region offers only its fixed view. A future left-view selector would register its views through the same panel mechanism, without an architecture change or automatically moving current content.

Stable identity and exact presentation

A target reference contains its semantic type, entity key, region, view and optional part. A thread can appear in the right Queue and in the main message view at once. Those are two presentations of one entity, and the brain must specify which one to signal. Never take the first DOM match.

Use session IDs for agents, node IDs for instances, workflow IDs plus stable task keys for workflow parts, and thread/message/attachment IDs for messages. Folder entries use folder ID, authorized relative path and location revision. Any component lacking a stable data key needs that key before exact targeting is supported. Do not derive identity from translated labels, row indices, text contents or rounded screen coordinates.

The map advertises static destinations and lazily enumerates dynamic objects. Mounted references register and unregister with React. Hidden kept views are marked hidden, not visible merely because their DOM exists. Entries in unloaded pages are discoverable through bounded data adapters; discovery does not activate them or mark them read.

Proposed command contract

These are design definitions, not new application files or an approved API. Store the eventual wire schema once and generate both TypeScript types and Python validation/tool definitions from it. Commands and target metadata come from feature registrations, not a separate handwritten brain map.

type Region = "left" | "right" | "main" | "overlay" | "footer";
type TargetRef = {
  region: Region;
  view: string;
  kind: string;
  key?: string;
  part?: string;
};

type UIRequest = {
  requestId: string;
  clientId: string;
  expectedNavigationRevision: number;
  expiresAt: number;
  operation:
    | { kind: "navigate"; commandId: string;
        args: Record<string, unknown> }
    | { kind: "indicate"; target: TargetRef;
        reveal: "never" | "navigate";
        style: "outline" | "circle" | "brackets";
        holdMs: number; label?: string }
    | { kind: "indicateRegion"; region: Region;
        expectedLayoutRevision: number;
        rect: { x: number; y: number; width: number; height: number };
        holdMs: number }
    | { kind: "clear"; cueId?: string };
};

type UIResult = {
  requestId: string;
  clientId: string;
  status: "completed" | "not_found" | "ambiguous" | "not_visible"
    | "blocked" | "unavailable" | "stale" | "cancelled" | "timeout";
  navigationRevision: number;
  effects: string[];
  cueId?: string;
  arrival?: "animated" | "static-reduced-motion";
  resolvedTarget?: TargetRef;
  reason?: string;
};
Feature registration interfaces
type Actor = "human" | "brain";
type CommandContext = {
  actor: Actor; clientId: string; requestId: string;
  expectedNavigationRevision: number; signal: AbortSignal;
};
type Availability = { available: boolean; reason?: string };
interface NavigationCommand<A> {
  id: string;
  argumentSchemaId: string;
  allowedActors: readonly Actor[];
  availability(args: A): Availability;
  effects(args: A): readonly string[];
  execute(args: A, context: CommandContext): Promise<UIResult>;
}
interface PipelineEdge {
  id: string;
  fromJunction: string;
  toJunction: string;
  region: Region;
  measure(): readonly { x: number; y: number }[];
  available(): boolean;
}
interface VisualTarget {
  ref: TargetRef;
  socketId: string;
  branchEdgeIds: readonly string[];
  parent?: TargetRef;
  label: string;
  visibility(): "visible" | "offscreen" | "hidden" | "occluded";
  measure(): DOMRectReadOnly | null;
  reveal?: { commandId: string; args: Record<string, unknown> };
  focus?: () => void;
  subscribeLayout(callback: () => void): () => void;
}

Registration is feature-owned. Mounted VisualTarget entries are local browser objects; functions and element references never cross the wire. The browser exports only authorized metadata and normalized geometry. Wire validation is generated from the schema; generic arguments are not an escape from validation.

Each registered command supplies a strict argument schema. The generic args object above is validated against that schema; unknown arguments and unknown IDs are refused. Target parts must belong to their registered type. The controller resolves pipeline edges from the target socket, not from arbitrary coordinates supplied by the brain. Rectangles are normalized to the selected region, bounded to [0,1], and bound to the current layout revision. They address a point through its region’s registered rail and an explicit clear terminal corridor. If no such corridor exists, the request is blocked. They never authorize a coordinate click or a free path across the screen.

Examples against the actual interface
  • Left database metric: indicate {region:"left", view:"fixed", kind:"teamServer", part:"database"}. A white signal travels from the orb into that metric. Nothing opens and no read receipt is sent.
  • Right Network: navigate panel.select with {region:"right", view:"network"}, then indicate a node’s cpu part using its node ID.
  • Focused main workflow tab: navigate workflow.open with the workflow ID; then workflow.tab.select with tab:"tasks". Resolve the task key after loading, scroll into view, then animate the white signal from the orb into that task and draw its arrival contour.
  • Existing main tab: main.tab.select selects Conversation or Folders directly. Selecting Thread, Queue, Network or Workflow requires its open entity or a command that supplies one. Do not select an empty dynamic tab.
  • Settings: settings.open with section:"team" calls the shared settings handler and waits for section scroll. It does not sign out, change membership or save fields.
  • Folder preview: resolve the folder ID and revision, choose main Folders, reveal the permitted relative path and open its preview through Contents navigation. Existing server read restrictions still apply.
Browser delivery, acknowledgement and multiple pages

Extend the existing authenticated UI connection with client identity, capabilities and request/result messages. Add server-side handlers beside the existing tool dispatch and expose schemas through jarvis_mcp.py. Consume the UI request in the frontend near jarvis.ts/ws.ts, with a dedicated controller rather than more view-specific branches in the voice parser.

Bind the request to the page that originated the human turn. Never broadcast navigation to all voice clients. If a background agent has no bound page, return available authorized clients and require an explicit target; do not select a random visible tab. Reconnect creates a new connection epoch. Expired commands are not replayed.

Validate ownership, scope, schema and capability before dispatch. Each client serializes navigation transactions, deduplicates request IDs and returns an acknowledgement only after the intended state is applied. The backend waits for that acknowledgement with a bounded timeout. A socket disconnect means unknown delivery until reconciled, not “shown.”

Capture the starting navigation revision. If the human changes views during an asynchronous reveal, cancel the stale sequence before it steals the view back. If the command already changed a view, report that partial effect rather than pretending to roll it back. Human input wins; no automatic restoration overwrites a later human selection.

Navigation can have effects: preserve them deliberately

queue.openItem changes queued placement to Active. followLink preserves placement, while showing the body can still trigger the existing read behavior. Selecting Agents clears its tab attention marker. Leaving a queue editor can save a draft. These effects belong in command metadata and results.

A plain indication defaults to reveal:"never". If the target is hidden, report that condition. A reveal-enabled request can navigate only under the existing authorization for that action and reports the associated effects. Background discovery must never invoke open handlers. Do not create a second preview path with different read semantics unless separately designed.

Sending, deleting, approving, changing settings, selecting an agent as a transmission recipient and answering a workflow decision are not generic navigation. Their controls are targetable, but execution stays with existing authorized application commands. The UI-control tool does not accept arbitrary JavaScript, CSS selectors, DOM clicks or URLs.

Programmatic navigation remains programmatic in humanActivity.ts; it must not advance the last-human-online timestamp. It also must not manufacture human approval.

The complete animation is the feature.

Every indication has a visible origin and a visible journey. The main brain orb emits in white. A white signal follows the background pipeline away from it, bright pulses travel toward the requested part, and arrival rings resolve into the target contour. An isolated circle does not satisfy this design.
RevealResolve the exact view, entity and part. Wait for it to become visible.
Emit · 220 msThe orb spins up and takes on white, using its existing transmission motion.
Travel · 1,400 msA restrained white route appears; three bright pulses visibly move from source to destination.
Arrive · 700 msTwo rings ripple from the endpoint. The requested part receives its white contour.
Hold & resetKeep the connection and contour visible, then fade both and return the orb to its underlying state.

Proposed preview timing is five seconds overall: emit 0–220 ms; first pulse travels 220–1,620 ms; arrival rings run from 1,620 ms; the connection holds until 4,400 ms and fades by 5,000 ms. Following pulses are offset by 170 ms. Production uses a shared timing definition so SVG motion, orb motion and arrival acknowledgements cannot drift apart. Longer explanations extend the hold, not the travel time.

Use the existing transmission visual grammar: thin core, soft glow, directional pulses and arrival rings. Attention is white. Message transmissions retain their own colours and data semantics. The pipeline map remains visible after the active signal fades. The white signal may end in an outline for a row, an ellipse around a number, or brackets around a panel; these are endpoint treatments after travel, not alternatives to the route.

A background pipeline map, not free routing

The background map is part of the interface even when no animation is running. A subdued neutral-white line leaves the brain upward into the main horizontal pipeline, following the existing transmission pattern. Fixed vertical rails descend in the gutters serving the left, main and right regions. Object branches leave those rails at visible junctions. In the preview the right rail uses the outer edge, as current transmissions do.

Every animation follows the same hierarchy: main orb → top pipeline → region rail → registered object socket → registered internal branch → exact part. The signal brightens only the edges it uses. Unused branches remain faint, making the pathway understandable before and after the pulse. The target highlight remains the arrival treatment.

Do not compute a shortest route through arbitrary open screen space. The route is selected from the registered pipeline graph. Every edge has a stable ID, parent junction, region and measured geometry. Resize changes its coordinates, not its relationship to the other branches. An unavailable edge makes that route unavailable; it does not authorize a diagonal shortcut or a new path across content.

Regions register rails in their reserved gutters. Object components register an entry socket and a clear local corridor. Their meaningful parts attach as leaf branches. The preview enters cards from their right edge and uses an internal right margin to reach a metric without crossing its label. Whole-row targets stop at their object socket. Production components must reserve corridor spacing rather than drawing a route over text.

Show the trunk, regional rails and visible object branches continuously. Reveal fine internal branches when the corresponding object is selected or addressed, so the map does not become a mesh over the content. Offscreen or unmounted objects do not leave misleading floating branches. Scrolling updates their socket positions on the fixed regional rail.

If a modal obscures a pipeline, use an explicitly registered modal branch or reveal the target through normal navigation. If neither is available, report blocked. Do not abandon the pipeline. A future canvas has its own registered internal branch graph connected through the canvas socket.

Reuse the existing animation machinery

RayLane.tsx already coordinates mainOrb.current.transmit(), the ray core/glow/pulse, arrival timing and cleanup. Orb.transmit() spins up, fills from the centre outward and leans in the launch direction. rayGeometry.ts currently assumes the upper lane and right-hand endpoint. Preserve those existing transmission paths and extract the reusable animation lifecycle, sampling and geometry interfaces into shared modules.

Add an attention effect channel with source: mainOrb, registered pipeline edge IDs, an object socket, a target part, white styling and an arrival contour. Do not manufacture a Transfer or invoke Endpoint.reached() from this channel: that would risk lighting agent tabs or applying receipt behavior. Instead, the shared visual renderer invokes an attention arrival callback that completes the UI request.

The orb currently has one transmission overlay. Production needs an effect arbiter: genuine message transfers keep their existing motion; attention waits briefly for the source effect to become available, with a bounded expiry. Once launched, do not let attention cleanup end another effect. Use ownership tokens for every orb effect and preserve the underlying listening/thinking/speaking state. The standalone preview invokes the existing white transmit effect directly because it has no concurrent real messages.

Hidden targets and navigation are part of the sequence

Default indication addresses visible content. When reveal is authorized: choose the region and view, open the entity, select the nested tab, load or expand the target, scroll it into view, and wait for stable geometry. Only then emit from the orb. For example, selecting right Network reveals the node first, then the white route travels from the orb into its CPU value.

A narrated multi-step journey can first animate orb-to-tab, apply its registered navigation, then launch a fresh orb-to-detail signal. Each leg starts at the brain; do not teleport an existing pulse into the newly opened view. The command contract should expose an ordered sequence with cancellation between steps rather than make the brain guess rendering delays.

Distinct lifecycle events are resolving, revealing, emitting, travelling, arrived, holding, fading, cleared and cancelled. The tool result reports success only after arrival, not after scheduling. Reduced-motion users receive the full static source-to-target connection plus target contour and an explicit static-reduced-motion result.

Movement, layers and cancellation

Use one shared animation-frame scheduler for active effects. Re-measure dirty geometry after resize, relevant scrolling, list commits and canvas movement. Keep progress on the current registered edge. If a layout change invalidates the edge or its junction, cancel and visibly relaunch from the orb after the registered pipeline settles. Never switch to an unregistered route. Never finish at a stale row position.

The attention overlay is pointer-transparent. Clip paths to authorized visible surfaces. A modal gets an overlay host in its own layer, with source-to-destination geometry transformed into the same viewport coordinate system. If the brain orb is concealed by a modal, reveal the source when permitted or report the obstruction; do not invent a second orb.

On route cancellation, human navigation, target removal, turn interruption or page disconnect, release only this effect’s frame callbacks, timers, route, contour and source ownership. Clear after the hold automatically. When real message transfers and attention paths coexist, separate their lanes where possible and keep attention pulses white.

For reduced motion, show a static white path joining the source and target without spinning, travelling particles or expanding rings. Announce the target and relationship to screen readers. A dark under-stroke gives the white path contrast on light surfaces. Keyboard focus is separate from visual arrival, and Escape must respect existing stop-speaking/dialog behavior.

DOM parts supply element references; canvas parts need projection adapters with visible bounds and occlusion state. Until an adapter exists, only the whole orb canvas is targetable. Cross-origin website internals and operating-system controls remain outside the application map. These limits must be visible in discovery rather than disguised by arbitrary coordinate clicks.

How new navigation stays controllable

Make brain access a property of adding a navigation command. A developer registers the command once. The UI renders its control from that registration, and the brain discovers it from the same registration. There is no second list to remember to update.
  1. Shared command primitive. Add registered navigation bindings for buttons, tabs, links, row activation, keyboard shortcuts, search, filters, pagination, expansion, scrolling and close/back. Each binding carries command ID, typed arguments, target and availability. Keep transient hover and animation state local; route state changes go through the dispatcher.
  2. Single route state. Replace private selected-tab state in RightPanel, CentreArea and nested views with shared feature-owned navigation state. Preserve existing mount/scroll behavior. Avoid competing useEffect setters selecting different centre views after one command.
  3. Required registration. New views supply a view ID, parent, mount readiness and reveal commands. New addressable object types supply stable keys, part definitions and pipeline sockets. Each part registers the branch edges connecting it to its object socket. CI rejects disconnected targets and edges that cross a reserved content area. Runtime assertions reject duplicate target presentations and dangling commands.
  4. Static enforcement. Add a TypeScript-aware lint rule restricting route-state setters to their owning dispatcher modules. Require registered navigation components or an explicit reviewed classification for interactive controls. Ban brain-specific querySelector/click navigation paths. Text grep alone cannot establish coverage.
  5. Manifest tests. Generate the navigation/target manifest from feature registrations. CI rejects a navigation control whose ID is missing, arguments do not validate, or command has no handler. Hidden and conditional views must be represented with availability reasons.
  6. Behavioral coverage. Run every registered navigation command from a test fixture through both its UI binding and brain adapter and compare resulting state and declared effects. Exercise actual DOM controls too; registry tests alone cannot detect a new unregistered button.
  7. Review gate. Every UI change declares whether it adds navigation, changes object parts or has no such effect. CI checks structural coverage, and the reviewer checks semantic classification. No tool can guarantee that arbitrarily written future code has been classified correctly without this boundary and review.

Brain discovery includes enabled/disabled status and reasons at runtime. A command remains discoverable when its target is unavailable, so the brain can explain the missing entity or prerequisite rather than hallucinating a click. Keep discovery bounded and omit secret field values and inaccessible object data.
